Reading and reproducing the reports

All analysis code and saved outputs are distributed within HTML. No standalone Rmd, R, Python or notebook source files are required from this repository. To read the reports, download the repository ZIP and open index.html in a browser; GitHub’s file view displays HTML source.

1. Obtain the annotation data

The study’s data deposit is OSF: K9CAJ. Place the three annotation CSVs in a local data/ directory at the repository root. The exact analysis inputs have the following file sizes and MD5 checksums; each R report also records its coded-data and source fingerprints.

2. Recover the embedded source

Open an OpenMx or lme4 G-theory HTML report and choose Code → Download Rmd. This recovers the authoring source already contained in that HTML. Save it alongside the corresponding HTML: under primary_analysis/ for OpenMx or supportive_analysis/lme4/ for lme4. Use the explicit data-path overrides below to resolve the root data/ folder. The primary source contains the full fitting engine, model definitions, numerical checks, resampling and reporting functions.

The agreement HTMLs show every code cell and saved output from the retained notebooks. Their input-path notes and package metadata are included in each report; adjust the displayed data directory for a local run. Prompts and annotation procedures are documented in the manuscript’s Supplementary Materials. Labelling notebooks are not included in this package.

The five updated lme4 reports also contain a Download the complete point-estimate outputs section, with 106 saved output files in total. The CSV tables and RDS fit summaries are embedded in the HTML and work offline. These output tables are separate from input data and native fit checkpoints.

3. Match the reported environment

The R reports record R 4.5.3, with OpenMx 2.22.11 for primary analyses and lme4 2.0.1 for supportive analyses. Use each report’s complete sessionInfo() listing for the remaining versions. Rendering uses rmarkdown and knitr, with Pandoc (included in RStudio). Required packages across the R reports include:

install.packages(c("OpenMx", "digest", "rmarkdown", "knitr", "lme4",
                   "dplyr", "numDeriv", "MASS", "pbivnorm"))

This command installs available versions; use the reported versions when comparing numerical results. The Python report metadata records the saved runtime where available; the notebooks do not contain a complete locked Python environment.

4. Rerun an analysis

After extracting the source and obtaining the data, run the following from the repository root for the primary Hate-Speech analysis:

rmarkdown::render("primary_analysis/uni_hate_speech.Rmd",
  params = list(data_dir = "../data", reporting_only = FALSE,
                reuse_fits = FALSE, reuse_bootstrap = FALSE,
                bootstrap_B = 1000, bootstrap_jackknife = TRUE,
                check_hessian = TRUE, threads = 1))

Replace the filename with another primary report for its outcome set(s). A full run fits all candidate specifications and the selected model’s bootstrap and jackknife; it can be computationally expensive. Embedded source defaults and the original run’s provenance remain visible. Cached-report replay requires the original saved objects; the command above performs a fresh fit.

For a fresh supplementary univariate Hate-Speech analysis, after obtaining both its annotation and sampled-item CSVs:

rmarkdown::render("supportive_analysis/lme4/uni_hate_speech.Rmd",
  params = list(data_dir = "../../data",
    out_dir = "../../outputs/rmd_lme4_point_only_20260910/hate_speech"),
  envir = new.env(parent = globalenv()))

Use a new output directory for a fresh run. The univariate reports automatically reuse saved point fits only when the data, scoring, source, settings and runtime fingerprints match. Their output path must contain rmd_lme4_point_only_20260910. Replace the report and output-directory names for Drug-Review or Mental-Health.

For the stacked Mental-Health multivariate analysis, which needs only its annotation CSV:

rmarkdown::render("supportive_analysis/lme4/mv_mental_health.Rmd",
  params = list(data_dir = "../../data",
    out_dir = "../../outputs/rmd_lme4_point_only_20260910/mental_health_multivariate",
    reuse_fits = FALSE, test_items = 0),
  envir = new.env(parent = globalenv()))

Use mv_drug_review.Rmd and a separate drug_review_multivariate output directory for the four-aspect analysis. Set reuse_fits = TRUE to rerender from compatible locally saved multivariate point fits. Fingerprint mismatches stop the report; choose a new output directory for a different run. The repository does not distribute those checkpoints.

All updated lme4 analyses compare eleven specifications by ML and report the selected Family 2 REML point estimates without bootstrap, jackknife or confidence intervals. The multivariate reports use the original submission’s stacked covariance restrictions: diagonal source variances and a shared residual. Mental-Health uses the current six flags and three OR groups; Drug-Review uses four aspects. See the supportive-analysis index for their scope.

5. Retained diagnostic reports

The new lme4 model fits report point estimates. The manuscript’s earlier facet-severity intervals are preserved in separate reports for Hate-Speech, Mental-Health, and Drug-Review. Each page contains the relevant historical source, saved results, input information and reproduction instructions. Reading those saved intervals does not require a rerun.

The focused Mental-Health and Drug-Review reports retain the earlier cross-trait diagnostics. Follow each page’s source and coding disclosures when reproducing those analyses. These archived diagnostic outputs are separate from the current stacked lme4 model comparisons and from primary OpenMx inference.
