What the three references mean

  1. Corpus status: the retained unified source CSV preserves its input status column. Exact matching of sample text to source statement recovers a consistent label for every sample item. Eighty-eight items match one source row; twelve match multiple rows whose status and screening labels all agree.
  2. Screening-model label: the screening notebook writes response label into u_label (cell 10), using gpt-4o-mini (cells 12 and 15). All 53,043 retained source rows record gpt-4o-mini-2024-07-18. The sampling notebook renames u_label to original_label (cell 8). The archived agreement notebook then renames it to human_label (cell 4); the variable name does not make it human annotation.
  3. Within-panel protocol reference: the stored gpt-4o-mini label under rubric prompt, temperature 0, and seed 1001. This is distinct from the earlier screening label, although it shares a model family and related protocol.

Cell numbers are one-based. Original source-row identity remains ambiguous for twelve duplicated texts, while their reference labels are unambiguous. The unannotated Combined Data.csv is absent from this revision tree; recovery uses the frozen unified export, not a newly downloaded corpus.

Calculation and checks

For a tied mode, the alphabetically first tied label is selected, matching the retained notebook’s Series.mode().iloc[0] rule. There are 124 tied cells. Quadratic-weighted κ uses NORMAL=1, STRESS=2, ANXIETY=3, DEPRESSION=4, BIPOLAR=5, PERSONALITY_DISORDER=6, and SUICIDAL=7. Macro-F1 averages the seven class-specific F1 scores, assigning zero to a zero-denominator class.

Both current input CSVs match the frozen files byte for byte. Every annotation row’s stored text hash matches its sample text. The script checks the complete crossed panel, all source-text matches, duplicate-label consistency, and all displayed MH values in S17/S18. Metrics are computed directly from the paired labels; no statistical models or annotation calls are run.
